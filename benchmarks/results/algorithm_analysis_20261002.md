# 本地算法分析：tile 划分、排序压缩与反向任务拆分

2026-10-02，RTX 5090，驱动 615.71.09，JAX 0.11.2、Flax 0.12.10、
Optax 0.2.8、CUTLASS DSL 4.8.0。分析依据为本地源码、现有 bicycle 数据集
与独占 GPU 实验。用户要求尽量离线后，未再使用网络。
完整样本、配置、源码 SHA256 和输入模型 SHA256 见 [JSON 记录](algorithm_analysis_20261002.json)。

本轮保留一个可选的 [8×8 bicycle 配置](../configs/bicycle_8x8.toml)，
训练接口继续使用现有 JAX/NNX 类型。生产默认值仍为 8×16：目前只测了一个场景，
较小 tile 会增加 pair 数，且测得的平均 PSNR 略低。两个新 kernel 原型均未合入，
生产源码与本轮开始时的快照完全一致。

| 相同输入与训练协议 | 8×16 | 8×8 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 固定百万容量完整 NNX 更新，三轮中位数 | 2.3671 ms | 2.0952 ms | 11.49% |
| 默认 30k 完整训练，三轮中位数 | 42.8869 s | 41.3787 s | 3.52% |
| 25 个留出视角平均 PSNR，再对三轮取均值 | 25.4926 dB | 25.4619 dB | — |

固定模型来自当前生产代码完成的 30k 训练，容量 1,000,000、活跃点 993,152，
最后一个 cluster 只有 64 个槽位。两种 tile 都重新加载同一 NPZ，重新初始化 Adam，
使用视图 0、SH3、Optax、8M pair arena、`bicycle_10k.toml` 的学习率设置，
预热 30 步后计时 500 步。按 16/8、8/16、16/8 的顺序交替运行。
全部运行只编译一个更新变体，开启 donation，无 overflow。
此实验重新拟合单个视角，不代表完整增密调度的提速。

完整训练使用原生默认 30k 调度，仅覆盖 `images="images_4"`、`eval=true` 和 tile 形状，
seed=0，169 个训练视角，实际执行 29,913 次更新。计时包含增密、剪枝、透明度衰减和
空间重排，不包含预加载、预编译与最终 checkpoint 写入。各轮均为八个编译变体，
开启 donation，无 overflow。训练与评估每 0.5 秒检查其他 GPU 计算进程，未检测到干扰。

表中用各自 tile 评估。额外用统一的 8×16 渲染器评估全部模型时，8×8 训练模型
平均 PSNR 为 25.4634 dB，相对基线低 0.0291 dB；用原生 8×8 评估则低 0.0307 dB。
差异主要随训练模型变化，渲染 tile 本身只改变约 0.0016 dB。
较小 tile 改变 half2 像素分组与统计归约，训练轨迹不要求逐位一致。
三轮单场景结果不足以证明质量等价，也不足以确定其他场景应使用的 tile。

可直接复验完整训练：

```bash
XLA_PYTHON_CLIENT_PREALLOCATE=false uv run --offline --extra cute jaxgs-train \
  /path/to/bicycle --config benchmarks/configs/bicycle_8x8.toml \
  --output /tmp/bicycle_8x8.npz
```

基线配置只保留相同的 `[model]` 覆盖项，使用默认 8×16。其它训练与运行参数相同。

重 tile 的工作量隔离实验支持继续优化任务划分。复用同一投影、8×16 可见表、
图像梯度、梯度尺度、最终透射率与最后贡献者，分别只保留最重的 1、16、64 个 tile。
保留 tile 内的 Gaussian 顺序，并重映射绝对 pair 索引。

| 反向工作量 | 保留的 splat 迭代数 | 中位耗时 / µs |
| --- | ---: | ---: |
| 全部 8,034 个 tile | 2,825,480 | 788.94 |
| 最重 1 个 tile | 2,408 | 547.44 |
| 最重 16 个 tile | 28,259 | 546.32 |
| 最重 64 个 tile | 90,796 | 544.80 |

每条路径预热 30 次，六轮交替各 150 次，包含输出清零、全图缓存读取和主机调用。
单个 tile 只占总迭代数的 0.0852%，保留它的耗时仍为完整反向的 69.39%。
这支持少数串行任务造成拖尾的判断；由于固定开销仍在，不能把 69.39% 全部归因于
该 tile，也不能把移除其他 tile 当作可用的渲染提速。

深度排序压缩原型按 128 槽位 cluster 筛出有正 pair count 的点，选择四分之一、
一半或完整排序容量，稳定排序后沿用原有 emission 与 tile 排序。
四个视角分别测试完整模型和每十个 cluster 保留一个的分散稀疏模型，共八组。
pair count、overflow、有效 Gaussian ID 前缀、tile offsets 和 point counts 均逐位一致。
每条路径预热 30 次，六轮交替各 200 次，但动态版本在八组中均慢 4.77%～8.54%，
因此未合入。预先用 CPU oracle 固定容量的诊断路径，在稀疏模型上仅节省约 3～5 µs，
在完整模型上也没有收益。该诊断不能作为逐步训练的动态实现。
这一早期探索仅在运行前后检查 GPU 进程，未使用后续实验的连续监测协议。

另一个原型复用原来的 8×16 表和前向缓存，将反向的像素对分组分别交给独立 warp。
每个分组重放原有纵向二次型差分，保留单像素的 alpha 与透射率计算顺序。
无统计、对称 conic 的反向从 855.91 降至 734.97 µs；三轮固定模型的完整更新
从 2.3756 降至 2.2540 ms，耗时减少 5.12%。这些数值属于该原型的独立对照，
不可与上面的 tile 对照混用。均在独占 GPU 下交替计时。

这个原型未合入。半精度梯度归约顺序发生变化，百万模型的颜色梯度相对 L2 差异为
1.76e-4；统计模式沿用旧路径，导致它与普通 VJP 的梯度不再满足既有一致性容差。
相关回归结果为 **108 项通过、1 项失败**，失败项为
`test_packed_staging_across_batches_matches_reference[True]` 的颜色梯度比较：
`rtol=1e-5, atol=1e-8`，540 个元素中 292 个超限，最大绝对差为 4.21e-5。
测试容差未放宽，这个原型也没有完整训练速度或质量结论。

下一项值得实现的算法是只对重反向任务做细分，同时让普通 VJP 与统计路径使用
相同的归约方式。这样有机会降低关键任务延迟，又能复用原来的 pair 表。
若进一步沿深度链分段，需要保存或恢复段边界的透射率与背后颜色。
前后两个片段在实数下可按 `(C_A + T_A*C_B, T_A*T_B)` 合并，但当前 half2 舍入与
提前终止使重排不保证逐位等价；应先验证边界状态、统计与梯度，再做完整训练比较。
