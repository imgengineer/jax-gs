# 损失梯度归约与光栅化反向算术优化

2026-10-01，RTX 5090，驱动 615.71.09，JAX 0.11.2、Flax 0.12.10、Optax 0.2.8、
CUTLASS DSL 4.8.0。基线是本轮任务开始时的工作区快照，包含此前的 uint8 目标读取
和 LiteGS 风格 JAX/NNX 接口。版本、四个 kernel 文件的 SHA256、修改补丁及验证结果见
[JSON 记录](kernel_arithmetic_20261001.json)。

本轮保留三处修改：loss kernel 写入图像梯度时归约最大绝对值，训练直接复用这个
归一化尺度；光栅化反向中偏移为 `(0, 1)` 的像素对直接使用上半部梯度作为一次和
二次矩；颜色和 alpha 的横向求和使用 half2 指令，减少 float32 转换。
公共 loss 的两个返回值保持原有约定，普通渲染的反向仍可自行计算梯度尺度。

全量 GPU 回归 **366 项通过**，Python 行和分支覆盖率均为 **100%**
（1,998 个语句、292 个分支结果），达到项目 99% 阈值。GPU kernel 的覆盖率
排除规则沿用项目配置，GPU 算术通过以下检查验证：

- 与任务开始时的 loss 实现比较四种图像尺寸及 uint8/float32 目标，八组 loss、
  图像梯度和尺度逐位一致，包括 822×1237 RGB 图像。
- 新增尺度回归覆盖边缘 tile、全零梯度、NaN 和 Inf 的传播。
- half2 求和检查让全部 65,536 种 half 编码出现在两个位置，再加入 65,537 组
  随机输入；有限结果逐位一致，NaN 标记一致。
- 完整训练、NNX donation、三种优化器和不同 tile 形状的既有回归通过。
- memcheck、racecheck、synccheck 各执行 10 项相关 GPU 用例，均报告零错误或风险。
  检查范围为 loss、光栅化反向及 half2 求和 kernel。

尺度比较使用 822×1237 RGB 图像，每条路径预热 30 次，交替执行八轮各 1,000 次。
光栅化反向使用相同的投影、可见表、缓存和图像梯度，预热 30 次、六轮交替各 150 次；
两条路径都自行归约图像尺度，用于单独比较光栅化算术。
固定模型比较使用同一百万行 PLY，补齐到 1,000,064 点，`images_4` 的
`_DSC8679.JPG`、SH3、Optax、8M pair arena，预热 30 步、计时 300 步，三轮交替运行。
六次运行均复用一个 JIT 变体，开启 donation，无 overflow。

完整训练沿用默认 30k 调度、`images_4` 和评估划分，包含增密、剪枝、透明度衰减与
空间重排，不包含预加载、预编译和 checkpoint 写入。两次均执行 29,913 次更新、
169 个训练视角，最终各有 993,152 / 993,152 个 Gaussian，
复用八个 JIT 变体，无 overflow。预热分别为 13.87 / 13.87 s。

小幅时间差不足以证明整个训练调度普遍提速。
