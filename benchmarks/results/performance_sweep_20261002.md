# 预编译裁剪与 SH 梯度传输实验

2026-10-02，RTX 5090，JAX 0.11.2、Flax 0.12.10、Optax 0.2.8、
CUTLASS DSL 4.8.0。使用本地源码和 bicycle 数据集，未联网。
[JSON 记录](performance_sweep_20261002.json)包含源码快照哈希、补丁、脚本和测量样本。

## 已采用：只预编译实际调度中的组合

训练和预编译共用每个 epoch 的 SH 阶数与统计开关，预编译先对这些组合去重。
169 个训练视角、默认 10k 预算时，只需要 SH0/无统计，以及 SH1～3 各自的两种
统计模式，共 **7 个组合**；此前固定编译 8 个。增密从 epoch 3 开始、间隔为 5，
第一个统计 epoch 是 5，此时已启用 SH1，因此 SH0/有统计不会用于实际训练。
只有一个 epoch 的 SH0 训练只编译一个组合。

LiteGS 的整 epoch 取整、SH 升阶、增密、透明度重置和视角顺序均保留。
默认预算仍为 10,000，bicycle 实际更新 9,971 次。

配置与 GPU 训练回归 **43 项通过**：包括混合分辨率、预编译中断后恢复原缓冲区、
重复模式去重、实际更新复用已编译模式、增密/重置、CLI 覆盖和 checkpoint。
这次回归期间 GPU 共享，因此仅报告编译组合减少，**不宣称已测得启动时间降幅**。

## 瓶颈与已排除的原型

本轮先用基线默认 10k 训练得到固定模型：百万容量、975,104 个有效点。
场景为 bicycle `images_4`，1237×822，169 个训练视角和 25 个留出视角，
8×16 tile、8M pair 容量、Optax，位置学习率周期仍为 30k。
该模型与此前 30k 实验不同，不能直接比较两轮的绝对耗时。

视角 0 的完整更新初测约 2.00 ms；20 次更新的设备 trace 中，主要 kernel 为：

| 环节 | 每次更新 / ms |
| --- | ---: |
| 可见 cluster 上的 Optax | 0.679 |
| 反向栅格化 | 0.440 |
| 前向栅格化 | 0.195 |
| 投影反向 | 0.183 |
| 投影前向 | 0.131 |
| 融合 loss | 0.087 |

这是定位热点的单视角 profile，不是多轮完整训练对照。
改变 Optax 的行块与 warp 数没有找到明显收益，部分更大的块反而变慢；
去掉单次更新外的动态循环也没有收益。Pallas 的 cache hint 原型因当前版本的
lowering/API 不兼容而不能编译，未改动已安装的依赖。

另一个原型将重 tile 的反向拆成四段：先按原来的 half2 顺序重放颜色与透射率，
保存段边界状态，再并行计算各段梯度。四视角、两种统计模式的前向与有效缓存
逐位一致，梯度/统计最大相对 L2 差异为 `1.944e-6`，但预处理成本超过并行收益。

| 固定投影、可见表和图像梯度 | 基线 / ms | 四段原型 / ms |
| --- | ---: | ---: |
| 反向，无统计 | 0.5320 | 0.8861 |
| 反向，有统计 | 0.5869 | 0.9978 |
| 前向 + loss + 反向，无统计 | 0.8558 | 1.2098 |
| 前向 + loss + 反向，有统计 | 1.0182 | 1.4424 |

表中是各自三批、每批 200 次的中位数；每个计时函数先预热 30 次。
上述成功的性能初筛均检查了 GPU 独占，运行中每 0.5 秒检查其他计算进程。
这些原型均未进入生产代码。

## 待独占测量：延后展开 SH 梯度

后续已在 2026-10-03 完成独占测量，并改进了梯度重建表达；结果与完整验证见
[训练优化记录](training_sh_20261003.md)。以下保留当时的原型状态。

SH3 的参数梯度每点有 48 个 float32 值，但它们可以由 3 个经过颜色截断遮罩的
颜色梯度和视线方向重建。原型让投影反向只写出这 3 个值，在可见 cluster 的
Optax 程序中重建 SH 梯度，再调用原来的 `tx.update`。
百万容量的 SH 梯度缓冲因此从 192 MB 缩至 12 MB；实际传输量随可见点数变化。
参数、Adam 动量和数值类型保持原样，高阶未激活系数的动量仍按原规则衰减。

- 独立 JAX 自动微分参考：SH0～3、3/4 通道布局、零方向和冻结槽位，共 **8 项通过**。
- 小场景连续 8 次更新，覆盖 Optax、Muon、CuTe，以及 SH0/无统计和 SH3/有统计。
  138 个状态数组均通过原有 `rtol=2e-5, atol=2e-6`，65 个逐位相同；
  最大绝对差 `1.193e-7`，最大相对 L2 差 `1.295e-7`。
- 15 个参数/动量缓冲区继续复用，JIT 缓存为一个变体，overflow 累积保留。

GPU 随后被 `jimm` 基准进程占用，显存一度超过 31 GB。SH 原型尚未完成独占计时、
真实场景质量对照和完整回归，因此**没有启用，也没有提速结论**。
补丁和检查脚本已保存在 JSON，独占后应先测相同输入的完整更新，再决定是否继续。

## 复现

从 JSON 指定的基线 commit 导出 `src/`，应用 `baseline_working_patch`，
再复制为各原型目录并应用 `candidate_patches`。全部 14 个补丁已验证能够恢复
记录中的源码；新训练调度改动另存为 `production_patch`。
`reproduction_scripts` 保存固定模型计时、反向计时、状态检查和独立公式检查脚本。
脚本中临时目录和数据集路径需换成自己的路径。固定模型用记录的 TOML 生成，
同一轮对照必须使用同一个 checkpoint。
